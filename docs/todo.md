# 1. 통합 테스트 및 MSW 모킹 구현

## 이유

- 핵심 기능에 대한 테스트 자동화가 가장 중요한 목표라고 판단하여 통합 테스트를 우선적으로 작성

## 목표

- **핵심 기능 검증**
  - 일정 생성, 조회, 수정, 삭제와 같은 애플리케이션의 주요 기능들이 외부 API와 올바르게 상호작용하는지 검증
- **종합적 검증**
  - 여러 모듈이 함께 작동할 때 발생할 수 있는 인터페이스 오류나 데이터 흐름 문제를 사전에 발견하고 해결
- **MSW 모킹**
  - 실제 서버 대신 Mock Service Worker(MSW)를 사용하여 네트워크 요청과 응답을 안정적으로 조작하며, 다양한 시나리오(성공/실패)를 테스트

## 작업 내용

1. **MSW 설정 및 핸들러 작성**
   - `handlers.ts` 파일에 주요 API 엔드포인트(GET, POST, PUT, DELETE)에 대한 모킹 구현
   - `handlersUtils.ts` 작성: 테스트 독립성을 위해 핸들러 초기화 및 리셋 로직 구현
2. **서비스 워커 초기화**
   - `browser.ts` 및 `main.tsx`에 서비스 워커 초기화 코드 추가
3. **핵심 기능 및 종합 검증 구현**
   - 실제 일정 생성, 조회, 수정, 삭제 기능을 통합 테스트 코드로 작성하여 MSW 모킹 환경에서 검증
   - 정상 케이스뿐만 아니라 예외 상황(예: 잘못된 입력, 네트워크 오류 등)에 대한 테스트 케이스 작성
   - 다양한 시나리오를 고려하여 UI와 API 간 상태 동기화 및 데이터 흐름 확인

# 2. 단위 테스트 작성

## 목표

- **세부 기능 검증**
  - 날짜, 시간, 이벤트 겹침 등 개별 유틸 함수와 로직이 의도대로 작동하는지 확인
- **경계값 및 예외 테스트**
  - 윤년, 월의 첫날/마지막, 잘못된 입력 등 경계 상황에 대한 정확한 처리를 검증
- **복잡한 로직 테스트**
  - 일정 알림 기능 등 복잡한 로직이 정확히 작동하는지 확인

## 작업 내용

- `dateUtils.ts`, `eventUtils.ts`, `notificationUtils.ts` 등 유틸리티 함수에 대한 단위 테스트 작성
- 각 훅(`useEventOperations.ts`, `useNotifications.ts` 등)에 대한 단위 테스트 구현

# 3. 테스트 독립성 및 환경 안정화 확보

## 목표

- **테스트 독립성 유지**
  - 각 테스트가 서로 영향을 미치지 않도록 상태 초기화 및 리셋 로직 구현
- **병렬 실행 안정화**
  - MSW 핸들러 설정을 통해 여러 테스트가 병렬로 실행되더라도 독립적이고 안정적으로 동작
- **핸들러 구현의 투명성 강화**
  - API 모킹 설정이 실제 API 스펙을 정확히 반영하여 다른 테스트와 일관되게 작동

## 작업 내용

- `handlersUtils.ts`를 활용하여 테스트 간 상태 격리 구현
- `setupTests.ts`에서 테스트 환경 설정 강화
- 공통 테스트 설정 및 헬퍼 함수 작성

# 4. 코드 리팩토링 및 컴포넌트 분리

## 목표

- **유지보수성 향상**
  - 코드를 기능별로 모듈화 및 컴포넌트 분리하여 유지보수와 테스트 확장이 용이하도록 개선
- **테스트 용이성 증가**
  - 각 컴포넌트를 독립적으로 테스트 가능하게 분리하여 리팩토링

## 작업 내용

- `App.tsx` 내 컴포넌트 분리
- 공통 기능을 훅(`useSearch.ts`, `useCalendarView.ts` 등)으로 추출
- 유틸리티 함수 모듈화 및 재사용성 강화
