# 1. 통합 테스트 및 MSW 모킹 구현

## 이유

- 핵심 기능에 대한 테스트 자동화가 가장 중요한 목표라고 판단하여 통합 테스트를 우선적으로 작성

## 목표

- **핵심 기능 검증**
  - 일정 생성, 조회, 수정, 삭제와 같은 애플리케이션의 주요 기능들이 외부 API와 올바르게 상호작용하는지 검증
- **종합적 검증**
  - 여러 모듈이 함께 작동할 때 발생할 수 있는 인터페이스 오류나 데이터 흐름 문제를 사전에 발견하고 해결
- **MSW 모킹**
  - 실제 서버 대신 Mock Service Worker(MSW)를 사용하여 네트워크 요청과 응답을 안정적으로 조작하며, 다양한 시나리오(성공/실패)를 테스트

## 작업 내용

1. **MSW 설정 및 핸들러 작성**
   - `handlers.ts` 파일에 주요 API 엔드포인트(GET, POST, PUT, DELETE)에 대한 모킹 구현
   - `handlersUtils.ts` 작성: 테스트 독립성을 위해 핸들러 초기화 및 리셋 로직 구현
2. **서비스 워커 초기화**
   - `browser.ts` 및 `main.tsx`에 서비스 워커 초기화 코드 추가
3. **핵심 기능 및 종합 검증 구현**
   - 실제 일정 생성, 조회, 수정, 삭제 기능을 통합 테스트 코드로 작성하여 MSW 모킹 환경에서 검증
   - 정상 케이스뿐만 아니라 예외 상황(예: 잘못된 입력, 네트워크 오류 등)에 대한 테스트 케이스 작성
   - 다양한 시나리오를 고려하여 UI와 API 간 상태 동기화 및 데이터 흐름 확인

# 2. 단위 테스트 구현

## 이유

- 통합 테스트는 전체 흐름과 기능 간 상호작용을 검증하지만, 단위 테스트는 개별 함수와 모듈의 정확한 동작을 보장함
- 복잡한 로직이나 조건 분기, 예외 처리 등의 세밀한 검증이 가능해져 코드 안정성과 유지보수성을 향상시킴

## 목표

- **유틸리티 테스트**

  - `dateUtils`:
    - `getDaysInMonth`: 월별 일 수 반환 검증
    - `getWeekDates`: 주간 날짜 배열 반환 검증
    - `formatDate`, `formatMonth`, `formatWeek`: 날짜 포맷팅 검증
  - `eventOverlap`:
    - `isOverlapping`: 이벤트 중복 검사 로직 검증
    - `findOverlappingEvents`: 중복 이벤트 탐색 검증
  - `notificationUtils`:
    - `getUpcomingEvents`: 알림 대상 이벤트 필터링 검증
    - `createNotificationMessage`: 알림 메시지 생성 검증
  - `eventUtils`:
    - 이벤트 필터링, 검색 및 정렬 기능 검증
    - 검색어 입력에 따른 결과 반환, 대소문자 무시 처리, 날짜 범위(주간/월간) 조건 적용 등 다양한 시나리오 테스트
  - `fetchHolidays`:
    - 공휴일 데이터 API 호출 성공 시 정상 응답 데이터 확인
    - 네트워크 오류, 잘못된 응답(예: 비정상적인 데이터 포맷 또는 빈 응답)에 따른 에러 처리 로직 검증
  - `timeValidation`:
    - 올바른 시간 형식(예: '14:30', '09:00')에 대한 유효성 확인
    - 유효하지 않은 입력(예: 빈 문자열, 'invalid', '25:00' 등) 및 경계값('00:00', '23:59') 테스트

- **Hooks 테스트**

  - `useNotifications`: 알림 생성 및 중복 방지 로직 검증
  - `useCalendarView`: 날짜 및 뷰 전환 로직 검증
  - `useEventForm`: 이벤트 폼 상태 관리 및 시간 검증 로직 확인

- **API 테스트**
  - `fetchHolidays`: 올바른 공휴일 데이터를 반환하고, 잘못된 입력에 대한 에러 처리 검증

## 작업 내용

- **유틸리티 함수 테스트**
  - `dateUtils`, `eventOverlap`, `notificationUtils`의 경계값 및 예외 케이스에 대해 충분한 테스트 케이스 작성
